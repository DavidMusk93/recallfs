WHALE：高效 Agent 交互不是提示词技巧，而是 Harness 优化

论文把 Agent 视为模型参数与可执行 harness 的联合系统。对无法训练权重的日常协作， 最重要的迁移不是照搬训练算法，而是系统化优化上下文、工具、控制流、错误反馈和终止条件， 并用独立任务集判断瓶颈究竟在 harness 还是模型。

可复用规范应该是“任务合同 + Harness 合同 + 评测与交替迭代协议”，而不是一份越来越长的万能提示词。

核心机制：性能属于系统，不属于模型

论文将模型参数记为 theta，将系统指令、工具 schema、上下文管理、 parser、执行逻辑、错误反馈与终止策略统称为 harness h。二者共同产生轨迹， verifier 再把轨迹映射为奖励。只改其中一侧，另一侧就可能成为移动中的瓶颈。

WHALE 的更新式是：先在当前 harness 下更新模型 theta[k+1] = ModelUpdate(theta[k]; h[k])，再在新模型固定时搜索 h[k+1] = HarnessSearch(h[k]; theta[k+1])。交替的价值来自减少 “对随后会变化的另一半过拟合”。

同一固定调度 (E, I) = (0.6, 6) 在三个任务域都优于对照组。 更强的证据来自机制分解：SearchQA 中 harness search 用 weight-only 约 5.79% 的 rollout 数达到相近峰值；数学任务中 harness-only 几乎无效，先做小幅权重更新后，同类 harness 搜索才开始有效。

论文的 rollout 成本不含 harness proposer 的计算；每个配置没有报告多随机种子、 方差或置信区间；图表与表格使用运行过程中最佳 test mean@8 点，因此不能把峰值差异 直接解释为稳定部署收益。

如何与 Agent 高效交互

先判断失败属于哪一层，再决定改什么。高效不是减少所有沟通，而是让每次沟通都消除一个 可观测瓶颈，并保持其他变量稳定。

Harness 瓶颈

典型症状是没有读取关键文件、工具参数不稳定、上下文被噪声挤占、错误后重复同一路径、 过早结束、交付字段缺失。优先修改输入合同、工具、上下文选择、失败反馈和停止条件。

模型瓶颈

在上下文充分、工具正确、oracle 清晰、预算足够后，仍持续出现同类推理或生成错误。 此时才切换更强模型、增加独立 reviewer，或在有数据与训练能力时更新权重。

  1. 先给任务合同。明确目标产物、范围、非目标、权威输入、可修改边界和验收证据。
  2. 让 Agent 先取证再修改。要求读取 governing docs、当前实现和真实失败，不接受只基于摘要猜测。
  3. 一次只改变一个机制。例如只改变上下文选择或错误恢复；不要同时换模型、prompt、工具和验收口径。
  4. 用保留任务验收。当前案例用于定位与修复，独立案例用于判断是否泛化；最终门禁不能与生成逻辑同源。
  5. 小步交替。短周期改 harness，必要时再切模型或训练；每轮达到最小证据量后，连续无改进即停止。
  6. 保留可回退证据。记录基线、变更、结果、失败样本、保留或回退决定，以及后继任务 ID。

可复用规范：固定结构，不固定答案

可以形成规范，但规范应约束协作协议和评测循环，不应固化某一任务的长 prompt。 最小可复用对象有四层。

层 稳定字段 用途
task objective、deliverables、scope、non-goals 阻止 Agent 把模糊目标替换成容易完成的近似任务。
context policy、governing docs、evidence、dependency order 把上下文选择变成显式边界，而不是全库搜索的偶然结果。
execution authority、tools、checkpoints、rollback、stop rule 明确何时自主执行、何时阻断、如何恢复和何时停止优化。
verification oracle、held-out cases、evidence ledger、handoff schema 区分“Agent 说完成了”和“外部证据证明满足合同”。 
Objective: <one observable outcome>Deliverables: <owned paths or concrete outputs>Scope / non-goals: <explicit boundary>Authoritative context: <policy and governing-doc paths>Execution authority: investigate, edit, test, commit, push; stop on <conditions>Verification: <independent oracle, E2E cases, thresholds>Return exactly: docs_read, anchor_results, ambiguities, changed_artifacts,                verification_evidence, successor_id

这段模板只提供入口和完成协议。长期事实留在版本化文档中，工具契约留在 harness， 运行结果留在 evidence ledger；不要把三者复制进每次 prompt。

采用边界

不应从论文推出“Agent 越自主越好”或“自动搜索 harness 一定省钱”。论文依赖固定 binary verifier、明确任务分布和大量 rollout；在真实工程里，错误 oracle 会稳定地奖励错误行为， 安全约束也不能交给搜索过程自行发现。
  • 只在结果可验证、样本可隔离、失败可回退的范围自动优化 harness。
  • 安全、权限、数据边界和不可逆操作是固定 policy，不属于可搜索变量。
  • 不要在最终 E2E 集上挑“最好的一次”；另设 development 与 held-out gate。
  • 评估总成本时计入 proposer、人工审阅、工具调用、失败重试和维护成本。
  • 跨模型复用的是合同和评测集，不是某个模型上偶然胜出的提示词文本。
