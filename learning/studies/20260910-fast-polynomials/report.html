Fast Polynomial Evaluation：少乘法不等于更快

这项工作把固定多项式的系数变成另一组参数，再生成共享中间值的算术电路。理论上，它把 monic degree-n 多项式从 Horner 的 n-1 次乘法降到 floor(n/2)+1 次；工程上，收益取决于乘法成本、依赖链、FMA、额外加法和数值稳定性。

先看结构：优化的是算术电路

Horner 把每一步都接在前一步后面。预处理链用更多加减法构造两个 affine form，再让一次乘法同时生成多个系数贡献；共享的 y、z 又允许后续两支并行。它减少的是昂贵的 field multiplication 和最长乘法依赖链，不保证减少总指令。

数学上的核心

预处理不是近似拟合，而是 coefficient space 的换坐标。对目标系数先求出参数 alpha，再固定一条 straight-line program；运行时只输入 x。degree 3 的暖身例子已经显示“一次乘法携带两个自由度”：

H2 = x*x; P3 = (x + alpha2) * (H2 + alpha1) + alpha0

展开后得到 x^3 + alpha2*x^2 + alpha1*x + (alpha1*alpha2 + alpha0)。因此可从目标系数依次恢复 alpha2、alpha1、alpha0。论文把这种 triangular decoding 扩展为递归的 compatible pairs，并证明在 characteristic 0 或 characteristic p > n 的域上处处可解。

C 可以直接表达

网页会生成 C。下面是 degree-9 reverse Bessel polynomial 的核心 evaluator；常数是系数预处理结果，不是运行时拟合参数。

double eval_P(double x) {    double y = (x + 11.0) * x;    double z = (x + y - 21.5) * (-x + y + 132.5);    double t = (x + y + z + 12803.75)             * (-x - y + z + 1254.75);    double u = (y + z + 17266.75)             * (-y + z + 1347.75);    double v = (x + t + 32741929.0) * x;    return u + v + 56100843.0;}

这段代码的价值不是手写技巧，而是 code generation：系数变化时必须重新运行受验证的 decoder/compiler，不能人工猜常数。有限域版本还需要正确的 modular reduction 或 carry-less multiplication kernel。

最有趣的反直觉现象

1. 少乘法与快是两个命题

目标机是 AMD EPYC 7Y83，GCC 12.2，固定 CPU 31 / NUMA 0。每个结果取 31 次样本中位数，再取三轮中位数。strict-FP 下，短依赖链改善 latency；八个独立输入已能填满乘法流水线，此时额外加减法拖慢 throughput。

目标机模式Horner ns/eval预处理链 ns/eval结论
strict-FP，串行依赖16.85213.498链快 19.9%
strict-FP，八路吞吐2.8373.684链慢 29.9%
FMA，串行依赖11.85213.088链慢 10.4%
FMA，八路吞吐1.4003.858链慢 175.6%

FMA 把 Horner 的 multiply-add 形状直接映射为八条 dependent vfmadd。预处理链虽然数学乘法更少，却有更多 affine-form 加减和更复杂的寄存器数据流。因此 operation count 只是成本模型，不是 wall-time 结论。

2. 精确恒等不代表浮点稳定

对 P(x)=x^9，五乘法链在有理数域完全正确，却需要非零 dyadic constants 彼此抵消来恢复八个零系数。C 测试在 x=2^-10 上得到 100% 相对误差，而普通乘法链精确得到 2^-90。

边界：论文明确指出，对“给定任意 coefficients，再解码成新参数”的 floating-point 场景，放大因子可能无界；degree 31 的样本甚至溢出。Horner 和 Estrin 仍是通用数值计算的默认选择。

3. 同一个电路在另一种数据语义下可以稳定

如果参数本身就是数据，例如随机 hash keys，那么不需要从任意目标系数反解出巨大、互相抵消的常数。有限域运算又是 exact 的。因此本文真正有说服力的应用不是普通 libm 多项式，而是 polynomial hashing、sketch、filter 和某些 prime-field evaluation kernels。

动态 coefficients、少量求值预处理不能摊销通常不值得。
任意 coefficients 的高阶浮点需要严格 backward/forward error 保证默认拒绝，除非 guard 证明误差可接受并可回退。
采用准则：先确认 field 和 coefficient semantics，再生成并验证 chain；最后在真实 caller、真实编译 flags、真实 CPU 上同时测 latency、throughput、codegen 和数值误差。只有这四项共同通过，乘法数下降才成为项目收益。

可信度与未覆盖范围

本地 demo 已通过 FIL-C、Zig 0.16.0 的 O0/O2/O3 和 ASan/UBSan；目标机 GCC 12.2 的 strict-FP 与 FMA 构建均通过正确性检查。反汇编确认 strict-FP evaluator 分别保留 8 与 5 次 scalar multiply，轮数放大 4 倍时 wall time 放大约 3.97 倍。PMU 因目标机权限返回 <not counted>，因此本文没有硬件计数器结论。

本 study 没有独立复跑论文的 GF(2^64) 或 prime-field 应用 benchmark；相应加速数字是论文证据，不是本地复现。C demo 只复现 degree-9 binary64 evaluator 的语义和成本权衡。
