Fast Time-of-Day：打断依赖链

把日内秒数转换成 hour、minute、second。关键优化不是先找 magic number，而是先把串行商余链重写成两条可重叠的数据依赖。

工程默认应先选 V1 division：它保留完整 uint32_t 输入契约，同时在目标机上把串行延迟降低 47.8%。只有在调用方明确保证日内范围且 profile 证明必要时，再考虑 V2/V3。
  • 47.8%V1 latency reduction
  • 56.5%V3 latency reduction
  • 30.0%V3 throughput reduction
  • 5validated scalar variants
问题边界 依赖链 定点算法 目标机实测 工程选择 证据与限制

问题边界

输入是已经归一化的一天内秒数，不是 Unix timestamp，也不负责日期、时区或闰秒。

Input
day_second in [0, 86399]
Output
hour [0,23] / minute [0,59] / second [0,59]
Excluded
calendar conversion、time zone、DST、sub-second、SIMD、23:59:60
Reference
Ben Joffe, Fast Time-of-Day

先改变依赖图

传统写法和 V1 的运算集合相近，但 critical path 不同。CPU 能否重叠工作，取决于数据依赖而不是源码看起来有几行。

Traditional

一条连续依赖链

+-------+    +------+
| input |--->| hour |
+-------+    +--+---+
                |
                v
           +----------+
           | hour rem |
           +----+-----+
                |
                v
           +----------+
           | minute   |
           +----+-----+
                |
                v
           +----------+
           | second   |
           +----------+
V1

两条可重叠链

              +---------------+------> second
          +-->| total_minutes |---+
          |   +---------------+   |
+-------+-+                       v
| input |                     +--------+
+-------+-+                    | minute |
          |   +-------------+ +---^----+
          +-->| hour        |-----+
              +-------------+
uint32_t total_minutes = time / 60;uint32_t hour = time / 3600;uint32_t second = time - total_minutes * 60;uint32_t minute = total_minutes - hour * 60;

令 t = 60q + s 且 q = 60h + m。那么 q=floor(t/60)、h=floor(t/3600)、s=t-60q、m=q-60h。V1 只是把同一恒等式写成了更适合乱序执行的形状。

定点算法：收益来自更强的输入合同

对常量除数 d 使用 M=floor(2^32/d)+1，再取 x*M 的高 32 位近似商。近似会在足够大的输入处提前进位，所以 range 是 API 合同。

V1 fixed-point

显式 reciprocal multiply

保持 V1 的两条独立链，把两次常量除法写成乘高位。结构清楚，范围受限。

V2 hi/low

低位不是废料

乘积高位给出商，低位表示向下一整数推进的定点小数；低位乘 60 后取高位得到余数。

V3 base-64

把 modulo 60 补成 64

利用 x mod D = (x + c*floor(x/D)) mod (D+c)，取 D=60,c=4 后用 &63。

Variant 最后正确输入 首个失配输入 结论
V1 fixed-point 2,257,198 2,257,199 覆盖日内范围
V2 hi/low 2,255,818 2,255,819 覆盖日内范围

若 API 接受任意 uint32_t duration，只有 Traditional 与 V1 division 可直接使用。采用任一定点版本时，必须在入口处执行并测试范围约束。

Scalar fidelity

Negative check

Correctness

结论只适用于该机器、编译器、flags 和 consumer。传统 loop 在 GCC 12 中保留一个 idiv，编译器代码生成放大了差距。

工程选择

场景 建议
普通日期库，尚无 profile 保持现状；不为纳秒级冷路径增加维护成本。
标量单次延迟敏感 优先 V1 division：收益来自依赖结构，且保持 full-range。
确认的日内热点 同时 benchmark V1 fixed-point、V2 和 V3；入口强制 [0,86399]。
SIMD / columnar batch 单独检查 auto-vectorization 与目标 ISA，不能沿用 scalar 排名。
signed 输入 先定义负值与 remainder 语义；不要直接照搬 unsigned mask。

证据边界

  • FIL-C 0.684 验证执行路径、内存安全与边界输出，不作为性能基线。
  • 目标机硬件 PMU 返回 <not counted>；本文不报告 cycles 或 IPC。
  • 保留的是三次 run-level median 汇总，不是 31 个 sample 的原始日志。
  • SMT sibling 未被独占，小幅差异仍可能受系统噪声影响。
