Toolchain issue:
  The first Apple Clang build linked libc++.1.dylib as
  @rpath/libc++.1.dylib and had no LC_RPATH. The cause was a
  /usr/local/lib/libc++.1.dylib shadowing the macOS SDK stub. Supplying the
  active SDK library directory before /usr/local/lib produced the expected
  /usr/lib/libc++.1.dylib install name.
