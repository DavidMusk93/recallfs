GenDB 若计入进程启动，总和为 492.08 ms，收益降到 1.14x。若 dispatcher 仅接纳 Q9/Q18，其余回退 DuckDB，总和为 340.38 ms、收益为 1.64x；计入 GenDB 进程启动后为 381.07 ms、仍有 1.47x。

Correctness：Q1/Q6/Q9/Q18 均 11/11 次精确匹配。Q3 仅 8/11 次 canonical SHA-256 匹配；另 3 次将 439855.3250 输出为 .32 而非 .33，且结果 JSON 直接保留具体单元格差异。独立 30 次探针又观察到 8 次 .32，因此 Q3 必须拒绝，而不是用一分容差掩盖。
测量边界：自预热后 DuckDB 的位置中位数稳定，但 GenDB 的绝对耗时仍有明显 position sensitivity。最终一轮中，Q9/Q18 在两个位置都获胜，Q1/Q3/Q6 都落后；小幅 iteration 差异仍不能当作已隔离的因果效应。

准备阶段还用 FIL-C 0.684 和独立 GCC 以相同的 MACHINE=MAC DATABASE=ORACLE WORKLOAD=TPCH 配置构建 dbgen；heap-use-after-free 负向控制被 FIL-C 拒绝，SF0.01 八张表逐文件同哈希且行数符合预期。结构化 preparation manifest 进一步绑定源码、参考结果、harness、二进制、存储、DuckDB 文件和 FIL-C 结果，运行前逐项验真。

收益来自什么

LLM 不在运行路径中。收益来自它在离线阶段找到并固化的物理结构与执行形态。

关键解释：GenDB 的产品价值是可执行反馈驱动的 physical-design search。Q1 iteration 1 从 83.22 ms 回退到 85.52 ms；Q18 从 8682.36 ms 降到 69.56 ms 的数量级变化才是本轮最强机制证据。

消融整体状态为 bounded_numeric_failures_recorded：Q1 的旧迭代和 Q3 best 出现过一分以内的非精确输出。被选中的 Q1/Q6/Q9/Q18 变体在本轮 11 次检查中全部精确匹配；Q3 仍按严格主门禁拒绝。

核心机制

GenDB 的新意不是 query compilation 本身，而是让 LLM 在真实执行反馈下跨 storage、plan、data structure 和 code generation 联合搜索。

图中的关键点是 authority 分离：LLM 可以扩大候选空间，但 SQL 语义、artifact 身份、promotion 和 fallback 仍由确定性组件掌握。

为什么从 JSON encoder 开始

Tide 已经有固定 schema 的 LLVM JIT 路径和真实负优化记录。第一版 JIT 把 column-major 变成 row-major，并在每个 cell 保留 host callback，steady-state 只有 legacy 的 0.49x 到 0.77x。后续真正的收益来自恢复 execution shape、减少 data movement 和收紧 layout。

适合的生成目标：受类型系统约束的 EncoderPlan 策略组合和 lowering 参数。
不适合的生成目标：有任意文件、网络和系统调用能力的完整 C++ 程序。

只输出 typed proposal，人工实现并复核。

Artifact 必须绑定什么

查询名不是 identity，硬件 fingerprint 也不够。可复用 artifact 的最小 identity 是：

logical_plan_digest
+ parameter_schema_digest
+ result_schema_digest
+ sql_semantics_digest
+ catalog_schema_epoch
+ storage_layout_digest
+ statistics_digest
+ data_visibility_contract
+ hardware_class
+ compiler_and_flags_digest
+ runtime_abi_version
+ generator_version
+ verifier_suite_version

若 kernel 只依赖 schema 和 cardinality guard，可以绑定允许的统计区间；若使用 query-specific derived data，则必须绑定 snapshot 或 partition epoch。

最终判断

建议 把 GenDB 作为 Tide 的离线优化搜索方法，不作为新的 query engine。先让它在 JSON encoder 的 typed plan 空间内证明稳定收益，再进入无副作用的 Velox leaf/subtree；完整查询模板加速必须等 content-addressed registry、独立 oracle、sandbox、shadow 和 rollback 同时就绪。

禁止路径：生产查询到达后，把原始 SQL 和数据交给有完整 host 权限的 Agent，现场生成、编译并执行 native code。
