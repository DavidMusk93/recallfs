## Upstream Claims At This Revision

- RingZero is a small learning project, not a production load balancer.
- The data plane is an eBPF program attached at XDP; the Zig control plane
  loads it and updates pinned BPF maps.
- A packet is matched by VIP, mapped through a per-VIP Maglev table, rewritten,
  and sent with `bpf_redirect()` or `XDP_TX`.
- The README attributes potential multi-tens-of-millions packet rates to
  native XDP, multi-queue NICs, and RSS, while explicitly saying the local veth
  demo does not establish that result.
- The repository provides `BPF_PROG_RUN` packet-rewrite verification and a
  source-side UDP load generator, but no checked-in result from a target NIC.

These are source claims, not RecallFS observations. The study separates them
from local tests and target-machine evidence.

## Archive Limits

- GitHub's rendered page exposed only a sign-in shell to the browser session;
  `git clone` provided the complete 18-file tree.
- No release tag, CI workflow, benchmark result, SBOM, or license was present.
- The BPF path is Linux-specific and could not be executed on the local macOS
  host.
- The source may change after the pinned revision; later conclusions must
  re-fetch and record a new revision rather than silently treating `main` as
  stable.
